# 文档资产格式规范（渲染器 + 数据模式）

> **本文件是 SFDS「viewer + data」文档产物模式的单一真相源。** 该模式此前分散存在于
> 各设计 skill 的实现约定中（development-standard §2.2 / §6 有描述性说明），本规范将其
> 升级为**产物准入规则**：任何新增的、面向人的设计文档产物必须通过本文的判定表与合规清单。
>
> **版本：v1.0** ｜ 依据：development-standard §2.2「结构化数据驱动文档」的操作化

---

## 0. 模式定义

```
design/{NN}-{stage}/
  ├── {stage}-viewer.html      ← 渲染器：只管表现（file:// 双击可开，无服务器、无构建）
  ├── data/
  │   ├── loader.js            ← 数据加载清单（files 数组登记全部数据文件）
  │   ├── {slug}.js            ← 数据：语义内容，挂载到全局命名空间
  │   └── CHANGELOG.md         ← 数据变更记录
```

**双向禁令（模式的核心不变量）：**

1. **数据文件禁止含表现信息**——不写样式、布局、HTML 标记（内容字符串本身除外）。
   这保证 AI 复查/转写时只读纯语义数据，不解析表现层。
2. **渲染器禁止硬编码语义数据**——实体名、规则内容、统计数字等必须来自数据文件
   （渲染器自身的界面 chrome 文案——标题、按钮标签——不在此列）。
3. **同一设计资产禁止平行叙述文档**——不允许为已 viewer 化的资产另维护手写
   Markdown 长文/架构书；人读全景由渲染器视图或派生数据视图（§3）提供。
   违反此条 = 制造第二真相源 = 漂移本身。

## 1. 适用范围与产物准入判定

| 产物意图 | 形态 | 例 |
|---------|------|----|
| 设计资产（供人阅读 + 供机器/AI 消费） | **viewer + data 强制** | 工作流、ER、API、页面设计、后端架构、审计档案、决策账本 |
| 派生文档（从数据机械/半机械生成） | **生成式 data + 渲染视图**（带 `generatedFrom` 版本戳，禁止手编） | 审计档案、约束卡片 |
| 过程记录（一次性快照，只追加） | JSON / Markdown | 门禁运行记录、TDD 设计文档、复查报告、CHANGELOG |
| 规范 / 方法论 | Markdown | SKILL.md、`_shared/*.md`、release policy |
| 原始输入存档 | 原样归档 | `01-raw-input/original-logs/` |

**准入判定问题（新产物出现时逐问）：**

1. 此产物会被机器/AI 消费吗（生成输入、一致性检查、追溯）？→ 会：**必须是数据文件**
2. 此产物需要人做阅读/分析吗？→ 需要：**必须有渲染视图**（优先作为现有 viewer 的新视图 + 新数据文件，而非新 viewer）
3. 两问皆否且属于一次性记录？→ 过程记录形态，豁免
4. 拿不准 → 按 viewer + data 处理（从严）

## 2. 数据文件约定

| 约定 | 内容 |
|------|------|
| 命名空间 | 每个设计域一个全局命名空间（如 `window.ARCH_DATA`），由所属 skill 在 SKILL.md 中声明；新 skill 必须注册，禁止复用他域命名空间 |
| 结构 | IIFE 挂载；文件头版本注释；多文件同名键合并由 loader 负责 |
| `_trace` 块 | 存在上游消费关系时强制（consumes / produces，见各 skill 定义） |
| 变更管理 | 同目录 `data/CHANGELOG.md`；同步螺旋更新须同时在决策账本记账（见 backend-architecture-design §4.2） |
| 人的批注 | 人的批注/结论是**第一手输入**，不是派生物——放独立数据文件（如 `audit-annotations.js`），手写合法；派生文件再生成时引用而不吞并 |

## 3. 派生数据约定

派生文档（审计档案、约束卡片等）：

- 由生成入口产出，**整体再生成**，禁止局部手编；
- 必须带 `generatedFrom`（来源资产清单 + 各自版本戳）与 `generatedAt`；
- AI 生成的叙述性字段必须显式标注来源（`analystNotes[].author: "AI"`），与人写的区分；
- 消费者（review / 门禁）校验版本戳与当前资产一致性，过期即报告。

## 4. 合规清单（新产物准入 + review 标准合规维度核验）

| # | 检查项 |
|---|--------|
| 1 | 产物形态符合 §1 判定表（设计类不是 md、记录类不强行 viewer 化） |
| 2 | 数据文件挂载到注册过的命名空间，且已登记进 `loader.js` 的 files 数组 |
| 3 | 数据文件无表现信息泄漏（样式/布局/HTML 标记）——启发式扫描 |
| 4 | 渲染器无语义数据硬编码（改名/改数后视图随之变化） |
| 5 | 无平行叙述文档（同一资产不存在手写 md 孪生） |
| 6 | 派生文件带 `generatedFrom` 版本戳且与当前资产一致 |
| 7 | `_trace` 块（适用时）完整；`CHANGELOG` 存在且更新 |
| 8 | viewer 经 `file://` 直接可开，无服务器/构建依赖 |

## 5. 变更管理

- 本文件随 `_shared/` 目录整体分发（项目级 ↔ 全局 `~/.agents/skills/_shared/` 同步），与 `consistency-check-format.md` 策略一致。
- 修改判定表/禁令/清单 → 升版本并同步检查各 skill SKILL.md 中的相关描述。
- 新设计域 skill 创建时，其模板必须内含 viewer + data 脚手架并引用本规范。
