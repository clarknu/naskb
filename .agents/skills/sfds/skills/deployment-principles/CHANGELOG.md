# DEPLOYMENT-PRINCIPLES · CHANGELOG

## [1.2.0-arb.1] - 2026-08-31
- **网络分层细则定稿**（CASE-022，consult `infra-service-isolation` v1.1.0 §2 + `deployment-config-guide` §10.4b 同源回收，以细则为准取并集）：
  - **中间件仅内网绑定**（`127.0.0.1`/内网 IP），⚠️ **禁止绑 `0.0.0.0` 对公网**；
  - **服务名必须 `{env}-{service}` 环境前缀**（同产品多环境共网 → 全网唯一，禁裸 `app`/`dify`，防同名 DNS 冲突）——关键；
  - **业务进程一律进 Docker**（禁宿主机进程跑业务）；
  - **跨产品禁止互访** + **访问路径判定**（自己网络内→服务名；不在→`host.docker.internal`/`127.0.0.1` 宿主端口）；
  - **对外可多线并存**（每线=主域名+公网可达端口+证书+子域→内网端口映射表，互为回退）；**Tunnel=Nginx 之前的可选前置层**（CDN/WAF），非默认部署模式；80/443 被拦时直连线走备用公网端口+通配符证书；
  - **多环境共主机每环境宿主监听端口必须唯一**；
  - §三 重构为「三原则 + 落地规则 8 条」；**评审清单网络项 3→8**；正反例增至 5 行网络项。

## [1.1.0-arb.1] - 2026-08-30
- **新增「网络访问拓扑（宿主机分层）」约束**（需求方 2026-08-30 确立）：① 公共中间件（Redis/PG/MQ）经**宿主机端口**接入（内网统一入口；Redis 原生→原生 Host 绑定，PG 容器→映射 Host）；② **一个项目一个 Docker 网络**——同项目管理（含全环境）在同一宿主机共用同一网络、服务名互访，仅公共资源经宿主端口；③ **Nginx 层统一对外**——对外只经 Nginx 反向代理 + 域名映射，业务容器/宿主端口不直接暴露公网。

- **评审检查清单**增补 3 项网络项（公共中间件宿主端口 / 一项目一网 / 对外统一入口）。
- **正反例**增补 3 行（网络-公共中间件 / 网络-一项目一网 / 网络-对外）。
- **参考案例**：consult 案例改为宿主网络分层表述；新增与 release-management §八 #17（默认直接域名映射、对外只经 Nginx/隧道兜底）的关系。
