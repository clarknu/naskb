## 运行规则（控制器遵守，人可读）

1. **读写分离**：分析类任务并行不限；改代码任务全仓库共用一把写锁，任何时刻最多一个任务处于执行/测试/修复。
2. **新鲜度门**：出队执行前，跑 `git diff <批准时commit>..HEAD -- <touches>`：无变化 → 直接执行；有变化 → AI 增量复核，结论三选一：照旧 / 微调后执行 / 失效打回待审批+原因。
3. **验证闸门（两档）**：执行完必须验证。有测试 → 跑 verify，失败带报错自动修复，最多 3 轮，仍失败 → ⛔ blocked；无测试模块 → 至少跑编译/类型检查/构建，通过后转「⏳ 待人工验证」。
4. **提交纪律**：一任务一 commit，message 带 `[T-xxx]` 前缀。
5. **熔断**：连续 2 个任务 blocked → 暂停出队，通知人。
6. **上线**：默认不含 deploy；如需自动化，拆为独立流水线阶段（构建/部署/冒烟/待放行），「启动发布」= 异步开始并交还控制权，生产环境停在「🔔 待确认」。
7. **任务粒度**：一个任务 = 一个可独立验证的闭环。过大就拆。
8. **零阻塞与事件回推**：编排器永不内联执行；执行一律后台子代理。后台在每个阶段边界写一条事件到本文件事件日志区，需要确认时写 NEED-INPUT 并置顶；用户答复由编排器转发，后台不中断继续执行。
