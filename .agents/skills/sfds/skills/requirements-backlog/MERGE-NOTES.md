# REQUIREMENTS-BACKLOG · MERGE-NOTES

> 本技能为**新生技能**（CASE-032），**无跨项目分叉、无需三方比对与仲裁版**（R-006）。因此本 MERGE-NOTES 记录"为何新增、与既有机制如何分工"，而非三方调和记录。

## 一、为何新增（方法论缺口）

流水线（raw-input → … → release）是**线性**的：新想法一进来就被当作"当前要做的"走完主链。但存在大量**不该现在做、却值得记住并孵化**的想法。该缺口此前由任何既有技能都不覆盖。

## 二、与既有机制的边界（分记、不混页）

| 机制 | 本技能与之关系 | 判定依据 |
|---|---|---|
| `consolidate-raw-input`（L2 输入卫生） | **语义正交**：它向后整理当前设计讨论的原始日志；本技能向前孵化未排期的未来工作项 | 方向相反、对象不同、不合并 |
| `tech-debt-register`（§10.7，CASE-025） | **不同**：它记"结论已定、暂不执行"的设计债；本技能处理"还没细化"的想法，多了"细化中"前置状态 | 状态位不同（终态 vs 孵化中） |
| `iterate`（迭代引擎） | **分工**：它是对当前状态的修正/新增/诊断；本技能是入口分诊，想法细化充分后**从它开始** | 上下游：本技能→iterate |

## 三、需求方定案（2026-09-02）

1. **形态**：独立轻 Skill（+自带过程资产/模板），非纯过程资产、非主链重技能；
2. **捕获/细化分两段**："细化中"为独立中间态；
3. **命名**：`requirements-backlog`（无后缀领域实体，与 `business-workflow`/`consolidate-raw-input` 同列）；
4. **"细化充分"门槛**：设计文档 §六 5 条，默认从严。
