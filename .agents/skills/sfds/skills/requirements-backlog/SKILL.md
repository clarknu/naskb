# requirements-backlog · 需求积压/中远期暂存机制

本技能是项目**主链 pipeline 入口之前的『需求管理分诊环』**：把那些"现在不做、但值得记住"的研发想法收进一个**项目侧登记册**，赋上状态机、按期回顾、孵化、再交接给能"从头迭代设计"的承载者（主链 pipeline / `iterate`）。

> 层归属：**L2 方法论主链**前端（输入卫生之后、主链入口之前的"需求管理"环），作为**常驻旁路**（stage=bypass）——它**不是**主链的阶段，而是随时可捕获/回顾的分诊动作。优先级 0（与 `development-standard`、`consolidate-raw-input` 同层的基础/入口类）。

## 一、它解决什么问题

流水线（raw-input → … → release）是**线性**的：新想法一进来就被当作"当前要做的"走完主链。但你的真实工作里，有大量想法**不该现在做**——它们不是当前迭代或 Paper 的一部分，却值得被记住、被孵化。

本技能补上的正是这个空档：**主链入口之前**，把这些想法**先捕获、暂存中远期**，等告一段落再**回顾**，挑出的**先细化**，细化充分再**纳入**整体方法论从头迭代设计。

### 与相邻机制的分工（互补，不重叠）

| 机制 | 方向 | 职责 | 本技能关系 |
|---|---|---|---|
| `consolidate-raw-input` | 向后 | 整理**当前设计讨论**的原始日志 → 结论文档 | **正交**：它是历史整理，本技能是未来孵化 |
| `tech-debt-register`（§10.7） | 终态 | 记**已定但推迟**的设计债（结论/暂缓原因/待还方向/触发条件） | **不同**：它默认决策已定；本技能处理**还没细化**的想法，多了"细化中"前置状态 |
| `iterate` | 下游 | 对当前状态的修正/新增/诊断 | **分工**：想法细化充分并纳入后，**从它开始**走；本技能只做入口分诊，不替它执行 |
| 主链 pipeline | 执行 | 线性推进已排期的开发 | 本技能是**入口之前**的分诊；纳入后交给它 |

## 二、执行流程（触发条件 → 步骤 → 输出）

> **先读**：本技能只读写项目侧过程资产 `docs/requirements-backlog.md`（登记册）与 `design/CHANGELOG.md`（记账一笔）。**红线**：绝不 Read→Edit→Write `design/`、`src/`、`tests/` 下的任何文件；把已细化的需求交给 `iterate`/主链时只做**交接**，不代为执行。

### 步骤 0：定位登记册

1. 优先读项目 `AGENTS.md` 或 `development-standard` 查 `docs/requirements-backlog.md` 路径（`development-standard` §1.2/§1.6 初始化时铺设）。
2. 如果**不存在** → 用技能同捆的 `templates/requirements-backlog.md.template` 铺设一份到 `docs/requirements-backlog.md`，再继续。
3. 读取现有登记册，确定 `RB-xxx` 当前最大编号。

### 步骤 1：判定意图 → 走对应动作

| 用户意图 | 动作 | 状态迁移 |
|---|---|---|
| 想记一个**新**想法（"先记下来"） | **捕获**（step 2） | → 暂存中远期 |
| 手头告一段落，想**回看** | **回顾**（step 3） | 挑出 → 细化中 / 其余保持 |
| 挑出某条要**细化** | **细化**（step 4） | → 细化中 →（满足门槛）→ 充分待做 |
| 某条**细化充分**，要做 | **纳入**（step 5） | → 纳入主链/走 iterate |
| 想**终止**某条 | **放弃/搁置**（step 6） | → 放弃 / 长期搁置 |

### 步骤 2：捕获（capture）

只做记录，**不展开、不排期**：

1. 新增一行登记：`RB-{下一个编号}`，状态=**暂存中远期**，登记日期=今天；
2. 记**原始描述**（需求原话，**不解读不改写**）+ **来源**（谁的什么时刻/哪次对话/哪个词）+ **标题**（一句话主题）；
3. **不**做细化、不排期、不改任何设计资产。

### 步骤 3：回顾（review）

手头工作告一段落后执行：

1. 过一遍登记册，标注每条当前状态；
2. 挑出**适合拎起来做**的 → 标记为"细选中"，进入步骤 4；
3. 其余 → 保持"暂存中远期"或按需转"长期搁置"；
4. 汇报："当前有 N 条中远期，其中 X 条适合拎起来，建议先细化哪条？"

### 步骤 4：细化（refine）

回顾中被挑出的那条，**先补充、细化，不立即执行**：

1. 逐项补全：**背景 / 范围（在不在当前项目域内、是否新增域）/ 约束 / 可验收口径 / 预判落点（大致落在哪些层/端/域）+ 触发条件**；
2. 每补一项，写进登记册对应 RB 的**细化记录**；
3. **判定"是否充分待做"**：按"细化充分门槛"（§三）逐条核对；
   - 满足 → 状态=**充分待做**；
   - 不满足 → 状态保持**细化中**，并列出"还差哪条"。

### 步骤 5：纳入（promote）

某条**已充分待做**且用户确认排期 → 交接给能"从头迭代设计"的承载者：

1. **更新登记册**：该 RB 状态=**已纳入**，记录交接去向与日期；
2. **交接（本技能不执行）**：
   - 若是**新域/新功能**（需要从需求源头建模）→ 提示是否从 `§8.1 business-workflow` 开始**从头迭代设计**；确认后移交主链；
   - 若是对**既有功能/设计**的修正/新增 → 移交 `iterate`（路径 A）；
3. 本技能任务**结束**——它只做入口分诊与状态推进，后续设计/实现由对应承载者负责。

### 步骤 6：放弃 / 长期搁置（drop / dormant）

- **放弃**：细化后评估不成立 / 需求已过时 → 状态=**放弃**，保留原文可回溯；
- **长期搁置**：反复回顾仍无动因 → 状态=**长期搁置**，不物理删除。

### 步骤 7：记账

每次捕获/推进/状态迁移后：

1. 更新 `docs/requirements-backlog.md`；
2. 在 `design/CHANGELOG.md` 追加一笔（`RB-xxx 状态变更`），保持记账纪律。

## 三、"细化充分"门槛（默认从严）

> **需求方 2026-09-02 定案：采用设计文档 §六 5 条，默认从严。** 以下**同时满足**才升"充分待做"；任一不满足即停在"细化中"。

1. **谁要解决的问题**——有明确目标用户/受益方 + 一句话价值主张；
2. **边界清晰**——明确**在/不在**当前项目域范围内，是否新增域；
3. **有可验收口径**——能描述"做成什么样算成"（不能是"更好用"这类模糊目标）；
4. **已有预判落点**——清楚大致落在哪些层/端/域（不必精确，但要能指认出大致归属）；
5. **无重大不确定阻碍**——若存在"要不要做"的开放疑问，状态停在"细化中"。

> 门槛过严 → 常卡在细化中；过松 → 过早进入主链又被打回。默认从严，实际使用中可按需放宽（这正是做成"登记册+状态机"而非一次成型的原因）。

## 四、过程资产与红线

### 4.1 唯一过程资产

- **`docs/requirements-backlog.md`**（登记册）——本技能的唯一产物。方法论只定义"必须记什么 / 怎么被引用 / 状态机"（模板见 `templates/requirements-backlog.md.template`），**内容由项目填**。

### 4.2 必记字段（schema）

| 字段 | 记什么 |
|---|---|
| 编号 | `RB-xxx`（递增，稳定不换号） |
| 状态 | 捕获 / 暂存中远期 / 回顾 / 细化中 / 充分待做 / 已纳入 / 放弃 / 长期搁置 |
| 登记日期 | YYYY-MM-DD（捕获时刻） |
| 标题 | 一句话主题 |
| 原始描述 | 需求原话（不解读、不改写） |
| 来源 | 谁的什么时刻 / 哪次对话 / 哪个词 |
| 细化记录 | （细化中追加）背景 / 范围 / 约束 / 可验收口径 |
| 关联链路 | 预判落点（哪些域/端/层可能涉及）+ 触发条件 |
| 动态时间线 | 各状态迁移的日期 + 动作说明（追加式） |

### 4.3 铁律

| # | 规则 |
|---|---|
| 1 | **登记 ≠ 排期**——登记只是把它钉住，明确"何时/在什么条件下才轮到它"；判定合格线=将来看到能直接接上、不用重新决策（缺"关联链路/触发条件"的登记视为无效） |
| 2 | **只碰登记册**——不 Read→Edit→Write `design/`、`src/`、`tests/` 资产 |
| 3 | **不代为执行**——把已细化需求交给 iterate/主链时只做交接（出计划 → 用户确认 → 由对应 skill 执行），本技能不自行实现 |
| 4 | **不丢原文**——原始描述不解读、不改写；放弃/搁置只改状态，不物理删除 |
| 5 | **捕获与细化分两段**——捕获时只记录；细化是回顾后的一次独立动作（"细化中"独立中间态） |

## 五、与其他技能的关系

- **前置**：`development-standard`（初始化时铺设登记册与模板）；不依赖 L1 pipeline-controller。
- **协作**：`consolidate-raw-input`（向后整理）语义正交；`tech-debt-register`（§10.7）记已定债，本技能记未细化想法。
- **下游交接**：`business-workflow`（新域/新功能从头迭代设计）/ `iterate`（既有功能修正/新增）。
- **可被 `/sfds requirements-backlog` 路由**：本技能为 SFDS bundle 子技能，无独立手势，经父技能 `/sfds` 点名到达。
